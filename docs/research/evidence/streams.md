## Y2: `.remote` server, TeamID.BundleID, `[.local]` default, hosts in Sources. Verdict: CONFIRMED, with additions

- **Remote URL:** `Models/Method.swift:19-21` defines `.remote` as `https://remote-production.youtubekit.dev`.
- **What the remote method sends:** `Remote/RemoteYouTubeClient.swift:21-33` opens a WebSocket to `<server>/v1?videoID=<id>`. It sets the header `X-AppID-v1: <appID>`.
  - `AppIdentity.swift:16-18` builds `appID = teamID + "." + bundleID` and sends it in plaintext.
  - `hashedAppID` (lines 21-25) is never used.
  - On macOS the order is: entitlement `application-identifier`, then `Bundle.main.bundleIdentifier` with teamID `""`, then a keychain probe (lines 29-35 and 59-62). A Developer ID app without that entitlement therefore sends `.<bundleID>`.
- **Missed by the claim:** the remote server can command the client to perform arbitrary HTTP requests. The server chooses the URL, method, headers and body. The client returns the full body, status and headers over the socket (`RemoteYouTubeClient.swift:40-64` and `118-136`), so the user's Mac acts as the server's HTTP proxy.
- **Default method:** `Method.swift:30-36` makes the default `[.local]` when `canImport(JavaScriptCore)` holds (macOS, iOS, tvOS, visionOS) and `[.remote]` otherwise. `YouTube.swift:82-90` maps an empty `methods` array to `[.local]` as well.
- **Can `[.local]` reach a non-YouTube host? No.** These are all the network call sites outside `Remote/`:
  - `YouTube.swift:105-109`: GET `https://youtube.com/watch?v=…&bpctr=9999999999&has_verified=1`.
  - `YouTube.swift:120-125`: GET `https://www.youtube.com/embed/<id>`.
  - `YouTube.swift:192-195`: GET the player JS URL. That URL is scraped from the HTML and resolved against `https://youtube.com` (`Extraction.swift:30-53`, regex `/s/player/…/base.js`).
  - `InnerTube.swift:103,160-179`: POST to `https://www.youtube.com/youtubei/v1/{player,…}`.

  The `.remote` branch (`YouTube.swift:291-295`) is the only path to another host. `metadata` and `livestreams` always run locally (doc comments at `YouTube.swift:41` and `305`). Stream (googlevideo) and thumbnail (i.ytimg) URLs are returned to the caller and never fetched by the library. JavaScriptCore has no network API, and the shim at `SignatureSolver.swift:34-55` stubs `XMLHttpRequest`.
- **Every hostname in `Sources/**/*.swift`:**

  | Host | Location | Role |
  |---|---|---|
  | `youtube.com` | `YouTube.swift:51,55`, `Extraction.swift:45,51` | Contacted |
  | `www.youtube.com` | `YouTube.swift:59`, `InnerTube.swift:103,171`, `SignatureSolver.swift:52` | Contacted, except `SignatureSolver.swift:52`, a JS `window.location` value |
  | `remote-production.youtubekit.dev` | `Method.swift:20` | Contacted only by `.remote` |
  | `www.reddit.com` | `YouTube.swift:123`, `InnerTube.swift:30` | Never contacted. Sent as the `Referer` header value and as `thirdParty.embedUrl` in the InnerTube JSON for EMBED clients |
  | `github.com` | `InnerTube.swift:63` | Comment only |

  The JS resources mention only `www.youtube.com` and `youtube.com` (URL templates) and `github.com` (comments).

## Y3: shared static cache in `nonisolated(unsafe)` vars, `YouTube` not Sendable. Verdict: CONFIRMED

- **Static cache:** `YouTube.swift:17-23` declares `nonisolated(unsafe) private static var __js: String?` and `__jsURL: URL?` under `#if swift(>=5.10)`. They are plain `static var` otherwise.
- **Unlocked access:** the cache is read and written without a lock at `YouTube.swift:194-199` and cleared at `:256-259`. This is the player base.js cache.
- **Not Sendable:** `YouTube.swift:12` declares `public class YouTube`, which is non-final with no `Sendable` or `@unchecked Sendable` anywhere (grep).
- **Per-instance state is also unsafe:** each instance has unsynchronized mutable caches (`_js`, `_videoInfos`, `_watchHTML`, `_fmtStreams`, … at `YouTube.swift:14-36`). Calling one instance from two tasks at once is also a race, not only the statics.
- **Unstructured tasks:** `concurrentMap` (`Extensions/Concurrency.swift:23-34`) spawns unstructured `Task {}`s, so cancelling the caller does not cancel in-flight InnerTube calls.

## Y4: `Stream` exposes no itag number, contentLength, size, fps or expiry. Verdict: PARTLY right

- **Public on `Stream`** (`Stream.swift:11-30,99-139`):
  - `url`, `itag: ITag`, `videoCodec`, `audioCodec`, `fileExtension`, `bitrate`, `averageBitrate`.
  - Deprecated: `mimeType`, `type`, `subtype`.
  - Flags: `isAdaptive`, `isProgressive`, `isDash`, `includesAudioTrack`, `includesVideoTrack`, `isNativelyPlayable`.
  - `videoResolution`: the nominal height from the static itag table (`ITag.swift:15`), not the real width or height.
- **Internal or private:**
  - `filesize` (`contentLength`) is `private` (`Stream.swift:32`).
  - `ITag.itag`, `ITag.audioBitrate` and `ITag.isHDR` are internal (`ITag.swift:12-53`).
  - The internal `StreamingData.Format` holds `width`, `height`, `fps`, `contentLength`, `approxDurationMs`, `audioSampleRate`, `audioChannels` and `audioTrack`. `StreamingData.expiresInSeconds` is also internal (`InnerTube.swift:212-236`).
- **Correction:** the itag number can be matched through the public `Collection<Stream>.stream(withITag: Int)` (`StreamQuery.swift:25-27`), though it cannot be read directly.
- Everything else (clen, dur, expire, real dimensions, fps) is only reachable by parsing the googlevideo URL query, or by forking the library, which the MIT license permits.

## Y5: player clients `[.visionOS, .web]`, iOS dropped over PoToken, HLS only for livestreams. Verdict: PARTLY right

- **Primary clients:** `YouTube.swift:364` sets `innertubeClients = [.visionOS, .web]`. They are queried concurrently, and order is preserved, so itag de-duplication favours visionOS (`:268-273`).
- **Fallback clients the claim omits:**
  - `.mediaConnectFrontend`, when no progressive stream is found (`:280-286`).
  - `.webEmbed`, when there is no `streamingData` (`:322`).
  - `.webCreator`, for the age-gate bypass (`:428-444`).
- **iOS history** (from `git log -G`):
  - `.ios` left the defaults on 2025-10-04 (`d62514c`, "new innertube client defaults to: tv, webSafari, web (same as yt-dlp)"). That commit does not mention PoToken.
  - A separate `iosDowngraded` client was added and disabled on 2026-01-29 (`0a197f5`, "Disabled iosDowngraded client (requires PoToken)").
  - visionOS was preferred and androidVR removed on 2026-08-18 (`71c0c33`, `e11371d`).
- **HLS:** `streams` uses only `formats` and `adaptiveFormats` (`Extraction.swift:365-376`). HLS is surfaced only through `livestreams` (`YouTube.swift:306-312`). `livestreams` returns any `hlsManifestUrl` and does not check whether the video is actually live.

## Y7: `yt-dlp_macos` is a PyInstaller-frozen Python. Verdict: CONFIRMED

- **How it is built:** `build.yml:364-366` runs `python3 -m bundle.pyinstaller --target-architecture universal2`. `bundle/pyinstaller.py:26-27` defaults to `--onefile`.
- **Mach-O layout:** the release asset is 37,146,048 bytes. It is a fat Mach-O (`cafebabe`) with an x86_64 slice of 73,808 bytes and an arm64 slice of 37,047,744 bytes.
- **PyInstaller archive:** the cookie `MEI\x0c\x0b\x0a\x0b\x0e` sits at offset 36,840,610, with pyvers 314 and pylib "Python". The 143-entry TOC includes:
  - `Python.framework/Versions/3.14/Python`
  - `base_library.zip`
  - `PYZ.pyz`
  - `pyiboot01_bootstrap`
  - `pyimod0*`

  At runtime the onefile binary extracts an embedded CPython 3.14 to a temporary directory and runs it.
- **Signing:** the arm64 slice carries an ad-hoc signature only. CodeDirectory flags are 0x2 (adhoc), there is no team ID, and the CMS blob is empty. It is not Developer ID-signed or notarized.

## Extra findings and risks

1. **Web-client URLs may fail:**
   - yt-dlp marks `web` HTTPS/DASH formats as requiring a GVS PO Token (`_base.py:71-94`, applied to `web` at `:97-107`) and drops them when no token is available.
   - YouTubeKit has no PO-token logic and still merges `.web` streams for any itag visionOS did not return.
   - Some returned URLs may therefore 403, and callers cannot tell which client a `Stream` came from.
   - **Plan:** use only the common itags (140/251 for audio), verify with a HEAD or range GET, and fall back to yt-dlp.
2. **"Made for kids" videos fail on visionOS:** they are not available with the `visionos` client (`_base.py:295`) or `android_vr` (`:226`). For those, YouTubeKit falls back to `.web`, which needs a PO token (see item 1).
3. **Dubbed audio is filtered:** `Extraction.filterOutDubbedAudio` (`Extraction.swift:487-494`) drops every audio format whose `audioTrack.displayName` does not end in "original". This is useful for us because we want the original language, but it depends on English display names (the `accept-language en-US` header is set).
4. **Itags missing from the table are dropped silently:** `Stream(format:)` throws on unknown itags (`Stream.swift:35-38`), and callers discard the error with `compactMap { try? … }`. `ITag.swift` DASH_AUDIO lacks 599, 600, 773 and 774. De-duplication by itag also means that DRC or alternate variants sharing an itag keep only whichever came first.
5. **No SABR handling:** formats without a `url`/`signatureCipher` (SABR-only responses) are dropped.
6. **Code signing:**
   - yt-dlp_macos is ad-hoc signed, with no Team ID, and it is a PyInstaller onefile that extracts and loads `Python.framework` from a temp directory at runtime.
   - Shipping it inside a notarized, hardened-runtime app requires re-signing. It will likely also need entitlements such as `com.apple.security.cs.disable-library-validation` and `allow-unsigned-executable-memory` for the extracted Python. This is not verified on macOS.
   - The onedir `yt-dlp_macos.zip` ("no auto-update") is easier to re-sign file by file.
   - Deno must be shipped or located separately (2.3.0 or later). Without it, yt-dlp falls back to the visionos-only jsless client set and warns that this mode is deprecated (`_video.py:2976,2994-2999`).
7. **Pass `--no-cache-dir` or `--cache-dir`:** the EJS script source order checks the cache before the built-in scripts (`ejs.py:259-264`). The yt-dlp cache directory also matters for sandboxing.
8. **Swift 6 consumer friction:** because `YouTube` is a non-Sendable class with async getters, a Swift 6 consumer will get "sending … risks data races" diagnostics when it holds one in an actor. Create instances per task, or wrap them in an actor, and serialize extractions because of the static `__js` cache.
9. **Cost per signature call:** every `applySignature` call builds a new `JSVirtualMachine` and evaluates the 361 KB meriyah bundle plus the multi-MB player JS (`Extraction.swift:397`). That is roughly two solver runs per video, so CPU cost per extraction is noticeable, though acceptable.
